# Typed action contract

Transactions contain one to one hundred actions and at most 50,000 numeric scalars or 256 node/link records. Closed action types are: `ensure_collection`, `create_object`, `set_transform`, `create_mesh`, `edit_mesh`, `create_curve`, `create_text`, `add_modifier`, `ensure_material`, `set_material_nodes`, `ensure_geometry_nodes`, `ensure_camera`, `ensure_light`, `set_world`, `set_render`, `ensure_armature`, `add_bone`, `set_pose`, `set_weights`, `ensure_action`, `insert_keyframe`, `write_pose_action`, `import_asset`, and `save_project`.

`write_pose_action` atomically creates or compatibly replaces one action on an existing armature. It accepts one to 4,096 unique bone/frame keys across at most 256 bones, an inclusive integral frame range, `reject` or `replace-compatible`, `BEZIER`, `LINEAR`, or `CONSTANT` interpolation, and only finite location, unit WXYZ quaternion, and positive scale channels. Bezier handles are auto-clamped. Inspection reports bounded channel/key/bone/property/interpolation summaries and a semantic SHA-256 digest that must reproduce after reopen.

Legacy `insert_keyframe` remains object-only. It accepts only `location`, `rotation_euler`, `rotation_quaternion`, or `scale`, a bounded integral frame, a compatible array index, and an existing active action.

Every action is a closed discriminated object. Names are bounded UTF-8 strings. Object/data-block references must exist or be aliases created earlier in the validated graph. File inputs are exact absolute files explicitly declared in `externalInputs`; writes are limited to the enrolled `.blend` and declared checkpoint targets. Options are type-specific closed objects. No action accepts Python, an operator name, RNA path, driver expression, UI coordinates, or arbitrary keyword bags.
